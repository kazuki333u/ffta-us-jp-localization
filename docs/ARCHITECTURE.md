# ビルドの仕組み

このリポジトリが**公式データを一切含まずに**日本語化ROMを生成できる理由を
説明します。

---

## 1. 基本方針

```
あなたのJP版ROM ──┐
                   ├─→ ビルドチェーン ─→ 日本語化されたUS版ROM
あなたのUS版ROM ──┘
                          ↑
                このリポジトリが提供するのはここだけ:
                  ・抽出ロジック
                  ・対応表 (レコードIDの組)
                  ・US版のみの内容に対する新規日本語訳
```

**このリポジトリに入っていないもの**

- ROM (US版・JP版・生成物のいずれも)
- 日本版の文章
- 日本版のフォントビットマップ
- 日本版・US版のグラフィック
- US版の英語原文
- 生成済みのバイナリ差分 (BPS等)

**このリポジトリに入っているもの**

- ROMを読み解くパーサとビルドチェーン (Python)
- 「JP版のこのレコード = US版のこのレコード」という**対応表**
  (数値のインデックスのみ)
- US版にしか存在しない内容に対する、**本プロジェクトが書いた日本語訳**
- それらを検証する監査コード
- ごく短い**識別子のラベル表** — ジョブ名44件、アイテム分類名29件など。
  これはレコードの並び順と件数を検証するためのもので、
  ROMのデータを複製したものではありません
  ([`PROVENANCE.md`](PROVENANCE.md) §4)。

---

## 2. 日本語はどこから来るのか

日本語の文章もフォントも、**ビルド時にあなたのJP版ROMから読み出されます。**

チェーンは JP 版と US 版の両方のテキストテーブルを解析し、
対応表 (`src/localizer/chain/data/*_pairs.json` 等) が示す組に従って
JP側のレコードをUS側へ移植します。移植されるレコード数は **11,166** です。

**フォント**も同様です。日本語グリフはJP版ROMから取り出され、
US版ROMのフォント領域へ新しいスロットとして割り当てられます。
リポジトリにはフォントファイル (TTF / ビットマップダンプ) を
一切含みません。

**グラフィック**も同じ方針です。UI画像、ゲームプレイ画像、
ワールドマップのラベル、そして **ジョブアイコン44枚** は、
JP版ROMのコンテナからビルド時に読み出し、
ゲーム自身の圧縮形式のまま US版ROMへ配置します。
リポジトリにはピクセルデータを1バイトも持ちません。

**アイテム情報の「装備可能ジョブ」ページ**についても同様で、
JP版ROMに元から入っている29件のレコードを読み出し、
本チェーンのグリフ割り当てを通してから配置します。

つまり **JP版ROMを持っていない人はビルドできません。** これは意図的です。

---

## 3. US版にしか無い内容はどうするのか

US版には日本版に存在しないミッション・シナリオ・システム文言があります。
これらには対応する日本語が**どこにも存在しない**ため、
本プロジェクトが新規に翻訳しました。

その訳文は `src/localizer/chain/data/` のマニフェストに入っています。
新規翻訳の総数は **1,332 エントリ** です。

### マニフェストが英語原文を持たない理由

翻訳作業時、各マニフェスト行は「US版のこのレコードは当時**この英語**だった」
という記録を持っていました。これは、対応表がずれた場合や別リビジョンの
ROMが渡された場合に、**間違ったスロットへ日本語を書き込むのを防ぐ**ための
整合性チェックです。

公開版では、この英語原文を**SHA-256ダイジェストに置き換えています**
(`original_english_sha256`)。

```
開発版:  "original_english": "I am unused to[4D]these sorts of..."
公開版:  "original_english_sha256": "9a3f...c2"
```

ビルド時、チェーンは**あなたのUS版ROM**から該当レコードを読み出し、
そのダイジェストを計算して照合します。

- **チェックの強度は同じです** — SHA-256 の完全一致です。
- **US版の脚本を再配布しません。**

置き換えた件数は **1,571 フィールド**です
(`tools/public_audit.py` の `retail-text` チェックが常時検証します)。

例外は2件だけで、`words:ico/8` (`/`) と `words:ico/9` (記号の並び) です。
これらは自然言語を含まず、ビルドがその値を**そのまま書き戻す**必要があるため
文字列のまま残しています。

## 4. チェーンの構造

ビルドは **28 の層**が積み重なった構造です
(自分の出力SHA-256を固定値で検証する層を数えたもの)。
各層は「ひとつ前の層の出力ROM」を入力に取り、自分の担当分を書き込みます。

```
pristine US ROM
  → 文字割り当て / 一括移植
  → s_text / words / pages 各テキストファミリの移植
  → US版のみのシナリオ (新規翻訳)
  → 名前入力キーボード
  → UIグラフィック / ゲームプレイグラフィック
  → ワールドマップ・メニュー・月名のラベル
  → バトルウィンドウ / メニュー座標
  → ミッションパネルのテンプレート
  → US版追加ミッション
  → 表示欠けの修正 (クエスト期限 / SYSTEM / OPTIONS)
  → ジョブアイコン (JP版ROMの44枚を移植)
  → アイテム情報「装備可能ジョブ」ページ (最終層)
= 日本語化されたUS版ROM
```

各層は**ひとつ前の層の出力SHA-256を検証**してから動きます。
どこか1層でも結果が変われば、その先の層が即座に停止します。

最終層は自分の出力を、固定された期待値
`F1D673A1966C6C42B6F2CEF157F11EF984BB61E6A2184D7F0F47AC17EE2CA695`
と照合します。

---

## 5. 再現性

ビルドは**決定的**です。同じ2本のROMからは常に同じバイト列が出ます。

検証方法は3段階あります。

1. **チェーン内部** — 最終層は同じ処理を2回実行し、
   2つの出力が完全一致することを確認します
   (`determinism.sha256_1 == sha256_2`)。
2. **`build.py`** — 完成したROMのSHA-256を固定値と照合し、
   一致しない限り出力ファイルを書きません。
3. **手動** — 別の `--work-dir` で2回ビルドし、出力を比較できます。

このリリースでは、独立した3回のビルド (作業ディレクトリを別にした
クリーンコピーからのビルドを含む) が
`F1D673A1...` で**バイト単位で一致**することを確認しています。

## 6. ディレクトリ構成

```
build.py                       公開ビルダー (入口)
requirements.txt               依存 (Pillow のみ)

src/localizer/chain/           ビルドチェーン本体 (52モジュール)
  ffta_sect.py                 ROMセクション解析     ┐ 上流由来
  ffta_parser.py               テキストパーサ          │ (GPL-3.0)
  ffta_charset.py, ...                                 ┘ NOTICE.md 参照
  ffta_jp_*.py                 各ローカライズ層 (本プロジェクト)
  ffta_us_source.py            英語ダイジェスト照合 (本プロジェクト)
  data/                        対応表と翻訳マニフェスト
  SYNC_MANIFEST.json           どのファイルがどこ由来かの機械可読な記録

tools/
  public_audit.py              公開前監査 (CIでも実行)
  sync_from_canonical.py       開発リポジトリからこのツリーを再生成する

tests/
  public/                      ROM不要のテスト (CIで実行)
  rom/                         ROMが必要なテスト (ローカルのみ)

docs/                          ドキュメント
```

`.build/` はビルド中の作業領域です。**あなたのROMのコピーが入ります。**
既定ではビルド成功時に自動削除され、`.gitignore` で除外されています。

---

## 7. 開発リポジトリとの関係

このリポジトリは開発リポジトリの**ミラーではありません**。
`tools/sync_from_canonical.py` によって機械的に導出された部分集合です。

導出時に行われること:

- 最終ビルダーが**実際に import する**モジュールだけを抽出
- 英語原文フィールドをダイジェストへ置換
- 探索的な解析ツール、実行時QAハーネス、証跡ダンプ、
  セーブステート、生成物は**一切持ち込まない**
- Git履歴も持ち込まない (このリポジトリは新規に作られています)

何がどう導出されたかは `src/localizer/chain/SYNC_MANIFEST.json` に
記録され、`tools/public_audit.py` の `provenance` チェックが検証します。

詳細は [`PROVENANCE.md`](PROVENANCE.md) を参照してください。
